# 需求监控模块测试用例

更新时间：2026-07-01

测试用例版本：v1.0.3

适用范围：当前已经完成的需求监控能力。

被测 H5 版本：v0.1.56 或更高。

## 1. 测试范围

本版本只覆盖已完成能力：

1. H5 入口、项目切换、加载提示、数据更新时间。
2. 待补充需求：按必填字段规则提示、点击任务跳需求总表并复制需求 ID。
3. 我的待办：只显示本人作为执行人的需求。
4. 组员待办：组长能看到自己负责组员的执行人任务。
5. 需求总表缓存：优先读缓存，文档变更后刷新。
6. 机器人需求明细查询和版本查询。
7. 后台管理页的连通性、摘要读取、异常扫描。

不包含未完成功能：

- 不测试 H5 创建需求。
- 不测试 H5 里直接编辑需求总表字段。

## 2. 测试前准备

```text
http://10.1.1.81:39200/
```

需求协作 H5：

```text
http://10.1.1.81:39200/demand-h5.html
```

- 所有测试地址统一使用本机内网 IP：`10.1.1.81`。

## 7. 缓存和扫描策略

说明：H5 不应每次打开都全量扫描需求总表。后台先读取企业微信文档变更信号，如果没有变化就返回缓存；如果有变化才重新扫描并刷新缓存。

| 用例 ID | 测试点 | 操作步骤 | 预期结果 |
|---|---|---|---|
| DM-CACHE-001 | 缓存返回 | 连续两次打开同一个 H5 页面 | 第二次加载不应明显卡住，无报错 |
| DM-CACHE-002 | 数据更新时间 | 刷新页面后查看数据更新时间 | 显示最近一次缓存刷新时间 |
| DM-CACHE-003 | 总表变更后刷新 | 修改需求总表一条数据，等待缓存周期或重新触发刷新 | H5 数据更新，数据更新时间变化 |
| DM-CACHE-004 | 页面返回 | 从 H5 点击任务打开需求总表，再返回 H5 | H5 不白屏；如触发刷新，应显示加载提示 |
| DM-CACHE-005 | 接口异常兜底 | 断网或企业微信接口异常时打开 H5 | 页面不崩溃；有旧缓存时优先显示旧缓存，否则提示读取失败 |

## 11. 重点风险

1. 企业微信内嵌浏览器的剪贴板权限可能和普通浏览器不同，点击任务后复制需求 ID 需要重点验证。
2. 首次扫描需求总表可能较慢；后续应优先走缓存。
3. 如果同事正在频繁编辑需求总表，短时间内看到旧缓存属于可接受现象。
4. 组长-组员关系依赖 `demand-workflow.rules.json`，人员调整后需要同步配置。
5. H5 只负责提醒和定位，不负责在页面内修改需求总表。
