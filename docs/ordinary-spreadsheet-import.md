# 企业微信普通表格与 Excel 转换

版本：EA v0.7.18，M06。

## 使用方法

1. 对1号机器人发送：`创建普通表格，名称叫：项目周报`，创建空的普通表格。
2. 转换 Excel：发送 `转成普通表格`，再在5分钟内发送 `.xlsx` 或 `.xls` 文件。
3. 也可以先发送文件，再在5分钟内回复 `转成普通表格`。只处理同一人、同一会话最近发送的文件。
4. 等机器人返回“转换完成”和链接后打开检查。发送 `取消表格转换` 可取消等待文件/指令，不撤销已经开始的转换。

群里使用时需要触发1号机器人回调。首次测试建议在与1号机器人的单聊中进行。单独发送文件不会立即创建文档；服务重启后需重新发送文件和指令。

## 内容范围

- 每个工作表保留名称及顺序，单元格按原行列位置写入，不整理、不汇总、不改写内容。
- 保留有效区域内的空行、空列、换行、空格、零值及文本前导零。无限的尾部空白区域不导入。
- 数字、日期、百分比按 Excel 保存的显示格式转成文字；不是可计算的原数据类型。
- 公式只写入已有计算结果，不在服务端执行公式。没有已保存结果时，整份文件在创建表格前拒绝；请在 Excel 中重新计算并保存。
- 合并区按单元格坐标写内容，不还原合并；不还原字体、颜色、列宽、图片、图表、宏、批注或外部链接功能。
- 隐藏工作表拒绝转换，先在 Excel 中确认内容并取消隐藏，避免意外公开隐藏信息。
- 创建者加入文档管理员列表，沿用企业微信文档应用权限；不额外开放外部/匿名访问。

## 限制与失败处理

- 附件最大10MB，解压总量最大32MB；最多20个工作表。
- 每表最多200列、10000个单元格，整份最多50000格，包含有效区域内空格子；文字总量最多2MB，单格最多10000字。
- 最多同时转换2份文件，同一人在同一会话同时1份。超限会提示重新发送。
- 下载最多30秒；解析使用 Worker、20秒和128MB堆限制。每个 API 请求最多30秒，不自动重试创建/写入，避免重复文档或子表。
- 写入后调用普通表格读取接口逐格核对，再核对工作表名称和顺序。中途失败会标注“未完成”，返回已创建表格地址，不伪报成功、不自动删除。
- 文件消息处理记录存放相对路径 `data/doc-creator/imports/`，相同消息重放/重启不再次创建。中断记录需重新发送文件才能发起新转换。
- 下载链接和解密密钥仅来自真实文件回调，不接受文字中的 URL、文件路径或伪造操作者；下载只允许公网 HTTPS，重定向同样校验。
- 日志包含任务摘要、处理阶段、工作表序号、行列数、校验结果和错误码，不记录文件正文、下载 URL 或解密密钥。

## 接口依据与验证

- 新建文档 `wedoc/create_doc`，普通表格固定 `doc_type=4`：https://developer.work.weixin.qq.com/document/path/97460
- 表格编辑 `spreadsheet/batch_update`：https://developer.work.weixin.qq.com/document/path/101168
- 工作表属性 `spreadsheet/get_sheet_properties`：https://developer.work.weixin.qq.com/document/path/97711
- 单元格读取 `spreadsheet/get_sheet_range_data`：https://developer.work.weixin.qq.com/document/path/97661
- 实测返回 `responses` 和 `grid_data` 位于顶层，兼容文档中的 `data.responses/data.result`。
- 不使用微盘上传/文档附件上传冒充在线表格转换。
- 回归命令：`npm run test:ordinary-spreadsheet-import`、`npm run test:doc-creator-routing`、`npm run check`、`npm run check:config`。
- 已用单独的合成测试文档验证创建、两个子表、空行空列、前导零、空格和跨1000行分块写入/读回；未导入真实业务文件。机器人真实附件发送到返回链接由用户上线后验收。
