# M02 人员分配参考交互预览

版本：v0.1.0；日期：2026-10-17。

## 本轮交付

用户要求先看最终呈现效果。本轮交付独立可操作预览，不代表 PRD V1 的业务算法与正式功能已完成。

- 页面：`src/admin/static/assignment-preview/index.html`，沿用 EA 需求进度管理的白底、项目筛选、紫色选中态和导航风格。
- 入口：现有 EA 静态服务的 `/assignment-preview/index.html`。也可以直接用浏览器打开 index.html，无构建和新服务依赖。
- 预览版本独立为 v0.1.0，不变更 EA 主程序版本，不改现有需求页面导航和权限。
- 页面从合成场景展示四岗位、项目/需求筛选、候选人比较、工作量/依赖/经验展开、粗估重算、风险确认、演示分配、协调承诺/无法满足、重置。
- 窄屏先显示需求列表，进入后显示候选人，保留返回列表；电脑采用左右布局。

## 数据与计算边界

- 全部人员、任务、历史关系、协调对象和工作日历为合成样例；固定演示快照为 2026-10-19，不是线上快照。
- 只在当前页面内存中保存演示选择。刷新或重置恢复初始示例；不读写真实运行数据。
- 不调用任何业务 API。页面 CSP 的 connect-src 为 none，不接入登录、真实角色授权、表格写回或企业微信通知。
- model.js 的日容量计算仅用于让调整粗估时页面有一致响应，是给定释放日下的单人离散演示调度，不是全局联合可行性求解器，不承诺算法最优或满足全部 PRD 验收。
- “当前条件支持”等结论均为示例；页面持续显示演示标记，并在候选结果旁注明非线上联合排期结论。
- 兼任同一人的已演示分配负载按人员 ID 合并；重新确认会去除本岗位旧分配后再计算，避免重复计数。
- 缺粗估展示数据不足。修改粗估后选择按钮禁用，重新分析后才恢复；有风险/数据不足的人选需勾选确认。
- 提交承诺后保留“已承诺待复核”；日期本身不足以判定联合排期通过。晚于要求的日期显示冲突；无法满足只在演示中返回发起人。
- 无真实后台权限能力，岗位切换只用于预览，不能复用为生产授权机制。

## 后续正式实施

1. 核查线上字段、工作日表、身份权限、人员可承接岗位与已开工历史证据，补齐最小模型。
2. 实施可复核的联合依赖计算、基线/新增影响与快照一致性，逐项覆盖 PRD AC01-AC30。
3. 把已确认的界面整合到真实需求进度管理，接入只读分析。
4. 单独受控开启负责人写回、版本冲突检查、协调持久化、通知补偿和变更重算。

## 验证

`node scripts/test-assignment-preview.js --model-only`：只运行合成场景基础断言。

`node scripts/test-assignment-preview.js`：还运行 Playwright 交互和响应式测试；需开发环境提供 playwright，或通过 NODE_PATH 指向已安装依赖。可设置 EA_PREVIEW_BROWSER=msedge 使用本机 Edge。截图输出默认 `.preview-test-output/`，不纳管。可用 EA_PREVIEW_URL 指定已部署预览地址、EA_PREVIEW_TEST_OUTPUT 指定截图目录。

覆盖：四类结果、截止缺口变化、跨岗位自然人合并、不重复分配、项目/岗位/搜索、空态、依据三视图、取消确认、粗估变更失效、风险确认、协调待复核和无法满足、重置，以及 320/390/768/1024/1440 宽度无横向页面溢出、图标/品牌图片加载、无脚本异常、无业务 API 请求。
