# M02 人员分配参考

## 真实只读接入（v0.2.0）

EA v0.7.20；日期：2026-10-19。以下为当前行为，后面的 v0.1.x 小节仅保留历史记录。

- 入口仍为 `/demand-h5.html?panel=assignment`。复用企业微信签名登录，岗位由服务端映射确定；普通组员无权访问，组长只看自己岗位，配置中的总兜底人可看三个岗位。
- 真实读取需求总表、岗位组长/组员配置、工作日子表；需求按项目和岗位筛选，只列真实待分配且本岗位未指派的任务，排除任务拆分和明确不参与的岗位。
- 候选人使用本岗位完整配置池，不局限于当前组长名下人员。候选人的有效正式负载按自然人跨项目、跨前端/后端/美术合计；目标项目筛选不缩小负载范围。
- 本轮没有完整的可承接岗位/是否可分配人员台账，因此来源明确标为岗位配置，资格仍需确认。多人分工、缺失剩余、缺少粗估的预占不能按零处理。
- 人日粗估只用于当前查询，刷新后不保存。不新增写接口，不修改负责人、正式耗时、剩余，不发送消息。原演示选择和假分配结果已移除。
- 分析展示已知负载下的累计截止容量缺口下界、加入任务前后变化，以及未知工作量、期限、上游依赖。工作日含今天和截止日；逾期有效工作量继续占用未来容量。
- 这是保守的只读容量参考，不是完整跨人联合排期求解器。依赖不明、人员资格未确认、日历不覆盖或负载不完整时，不宣称确定可行；历史经验未接入，不展示合成经验。
- 首次访问按需读取全表；服务端短时缓存和共享进行中请求，切任务、改粗估复用快照。手动刷新可强制重读，不启动额外轮询或后台推送。
- 新增 `GET /api/dev-progress/assignment-reference`，身份只能来自已验证 session，忽略 query/header 中的姓名。角色越权返回 403，匿名返回 401。响应禁止缓存。
- 保留 iframe 不同源沙箱和 `connect-src 'none'`。父页面仅代理固定只读接口，白名单 query，项目由父页当前选择决定；不向子页面传 token、Cookie 或原始全表。
- 日志记录查询角色、结果、任务/候选数量、缓存命中、耗时，不记录 Secret、完整需求正文或原始全表。真实数据不纳入版本控制。
- 日期时间戳按上海日期解释，工作日读取使用独立的时区参数和缓存键，不改变原需求监控的默认日期解释。读取实际工作日表，不自行排除表内周六；本轮验证覆盖至 2026-12-31。

验证入口：`npm run test:assignment-reference`、`npm run test:assignment-ui`。后端测试使用隔离数据；UI 测试使用明确的测试 fixture，不向生产总表写入。线上验收只读查询，匿名鉴权和版本状态另行验证。

后续独立阶段：补人员资格台账、历史开工/粗估记录和联合依赖求解，再受控开启负责人写回与并发校验。

## 数据与计算边界

- 全部人员、任务、历史关系和工作日历为合成样例；固定演示快照为 2026-10-19，不是线上快照。
- 只在当前页面内存中保存演示选择。刷新或重置恢复初始示例；不读写真实运行数据。
- 不调用任何业务 API。页面 CSP 的 connect-src 为 none，不接入登录、真实角色授权、表格写回或企业微信通知。
- model.js 的日容量计算仅用于让调整粗估时页面有一致响应，是给定释放日下的单人离散演示调度，不是全局联合可行性求解器，不承诺算法最优或满足全部 PRD 验收。
- “当前条件支持”等结论均为示例；页面持续显示演示标记。
- 兼任同一人的已演示分配负载按人员 ID 合并；重新确认会去除本岗位旧分配后再计算，避免重复计数。
- 缺粗估展示数据不足。修改粗估后选择按钮禁用，重新分析后才恢复；有风险/数据不足的人选需勾选确认。
- 无真实后台权限能力，身份和岗位切换只用于预览，不能复用为生产授权机制。
