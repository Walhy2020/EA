# 需求协作 H5 流程测试说明

更新时间：2026-06-18

## 当前可测试范围

当前流程已经可以测试到：

1. 提出人创建需求草稿。
2. 被勾选的组长收到自己的待办。
3. 组长补充规则里配置的字段。
4. 单个组长提交后，该组长待办消失。
5. 所有组长都提交后，草稿流转到提出人最终确认。

当前还没有实现：

1. 提出人点击最终确认。
2. 写入需求总表。
3. 企业微信机器人主动推送组长待办。

## 测试入口

本机入口：

```text
http://127.0.0.1:39200/demand-h5.html
```

模拟不同企业微信中文姓名，在地址后加 `userName`：

```text
http://127.0.0.1:39200/demand-h5.html?userName=李晶晶
http://127.0.0.1:39200/demand-h5.html?userName=王谦
http://127.0.0.1:39200/demand-h5.html?userName=时振兴
```

说明：

- `李晶晶` 用来模拟提出人。
- `王谦` 用来模拟 UI 组长。
- `时振兴` 用来模拟策划组长。
- 当前身份来自 URL 参数，后续接企业微信真实身份后会改成自动读取。

## 测试前确认

1. EA 后台正在运行。
2. 页面右下角版本号至少是 `v0.1.36`。
3. 测试数据暂存在：

```text
data/demand-collaboration/drafts.json
```

## 完整测试步骤

推荐先用多身份测试驾驶舱观察完整流转：

```text
http://127.0.0.1:39200/demand-flow-test.html
```

这个页面会同时打开：

- `李晶晶`：提出人，默认停在 `创建需求`。
- `王谦`：UI 组长，默认停在 `我的待办`。
- `时振兴`：策划组长，默认停在 `我的待办`。
- `刘晓明`：动效组长，默认停在 `我的待办`。
- `胡锦南`：前端组长，默认停在 `我的待办`。
- `王文静`：后端组长，默认停在 `我的待办`。
- `高文盛`：测试组长，默认停在 `我的待办`。

每次创建或提交后，点击测试驾驶舱里的 `刷新全部`，就能看到不同身份窗口里的待办数量和详情变化。

### 1. 提出人创建草稿

用提出人身份打开：

```text
http://127.0.0.1:39200/demand-h5.html?userName=李晶晶
```

填写：

- 项目：任选一个，例如 `恶魔高校`
- 需求名称：填写一条测试需求，例如 `测试需求协作流转`
- 需求类型：默认 `新功能` 即可
- 规模类型：任选
- 优先级：任选
- 需求内容：填写测试说明
- 链接地址：可不填
- 组长：默认全选，也可以只保留一两个组长方便测试
- 需求设计交付日期：选择日期
- 更新时间：页面会按项目默认带出，也可以手动改

点击：

```text
生成需求草稿
```

预期结果：

- 页面提示草稿已保存。
- 页面切到 `待补充需求`。
- 草稿状态显示 `待组长补充`。

### 2. UI 组长处理待办

用王谦身份打开：

```text
http://127.0.0.1:39200/demand-h5.html?userName=王谦
```

点击：

```text
我的待办
```

预期结果：

- 如果创建草稿时勾选了 `UI组长`，这里会看到一条待办。
- 点击待办后进入详情页。
- 页面显示 `组长视角：UI组长待补充`。
- 页面显示 UI 组长需要补充的字段：
  - `UI制作交付日期`
  - `UI监修完成日期`

填写日期后点击：

```text
保存补充
```

预期结果：

- 王谦的 `我的待办` 数字减少。
- 如果还有其他组长没提交，草稿仍是 `待组长补充`。
- 如果只有 UI 组长一个人，草稿会直接变成 `待提出人确认`。

### 3. 策划组长处理待办

用时振兴身份打开：

```text
http://127.0.0.1:39200/demand-h5.html?userName=时振兴
```

点击：

```text
我的待办
```

预期结果：

- 如果创建草稿时勾选了 `策划组长`，这里会看到一条待办。
- 点击待办后进入详情页。
- 页面显示 `组长视角：策划组长待补充`。
- 页面显示策划组长需要补充的字段：
  - `内网验收/测试完成日期`
  - `正式验收/测试完成日期`

填写日期后点击：

```text
保存补充
```

预期结果：

- 时振兴的 `我的待办` 数字减少。
- 如果所有被勾选组长都已保存补充，草稿状态变成 `待提出人确认`。

### 4. 提出人查看最终确认待办

重新用李晶晶身份打开：

```text
http://127.0.0.1:39200/demand-h5.html?userName=李晶晶
```

点击：

```text
我的待办
```

预期结果：

- 可以看到一条提出人最终确认待办。
- 进入详情后状态是 `待提出人确认`。

注意：

- 当前 `最终确认` 按钮还没有接真实后台逻辑。
- 当前不会写入需求总表。

## 建议测试组合

### 最小测试

创建草稿时只保留：

```text
UI组长
```

然后只用王谦测试一次 `保存补充`。

适合快速确认：

- 草稿创建是否正常。
- 王谦待办是否出现。
- UI 补充字段是否出现。
- 保存后是否流转到提出人确认。

### 多组长测试

创建草稿时保留：

```text
UI组长
策划组长
```

测试顺序：

1. 王谦先保存 UI 字段。
2. 确认草稿仍是 `待组长补充`。
3. 时振兴再保存策划字段。
4. 确认草稿变成 `待提出人确认`。

适合确认：

- 单个组长完成不会提前流转。
- 所有组长完成才流转。

## 失败时怎么看

如果页面没有待办：

1. 确认 URL 里的 `userName` 是否是组长姓名，例如 `王谦`。
2. 确认创建草稿时是否勾选了对应组长。
3. 确认项目下拉是否和创建草稿时一致。

如果点击保存补充提示缺字段：

1. 检查页面上所有日期字段是否都已填写。
2. 组长补充字段来自：

```text
config/demand-workflow.rules.json
```

如果要清理测试数据：

```text
data/demand-collaboration/drafts.json
```

目前建议让 Codex 帮你清理，避免误删真实草稿。
