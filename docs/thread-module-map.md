# EA 主会话与模块会话协作规范

文档版本：v0.1.0

## 1. 会话职责

### 主会话

主会话只负责：

- 明确业务问题、目标用户和使用场景。
- 确认需求范围、优先级、边界和验收标准。
- 判断需求属于哪个功能模块。
- 生成模块会话可直接执行的完整提示词。
- 审核跨模块影响、上线结果和遗留问题。

主会话原则上不直接推进大段模块代码，避免需求讨论和实施记录混在一起。

### 模块会话

模块会话只负责：

- 阅读仓库根目录 `AGENTS.md` 和本模块现有实现。
- 按主会话交付的提示词实施，不自行扩大需求范围。
- 完成代码、配置、日志、测试、版本记录和必要的 EA 重启。
- 返回改动文件、验证结果、风险、边界和未完成事项。
- 遇到跨模块决策时停止扩展，回主会话确认。

## 3. 模块归属规则

- 一个需求只指定一个主责模块。
- 只调用另一个模块公开能力时，不增加第二主责模块。
- 需要修改共享启动、路由、管理接口或公共发送器时，由 `M00 EA 核心集成` 负责最终集成。
- `M02 需求进度监控` 和 `M03 盯梢系统` 不自行修改公共频控策略；公共送达策略归 `M04 消息与送达通道`。
- 模块会话不得清理、回退或覆盖其他会话留下的工作区改动。
- 运行数据只用于读取和验证，不直接修改真实任务，除非主会话明确授权。

## 4. 主会话确认清单

生成模块提示词前，主会话需要确认：

1. 当前问题和期望结果。
2. 使用人、责任人和权限范围。
3. 入口、页面、卡片或机器人交互方式。
4. 状态流转和失败处理。
5. 提醒频率、时间规则和重试策略。
6. 是否影响真实数据或现有任务。
7. 是否需要兼容旧卡片、旧链接和旧任务。
8. 验收场景和可接受的边界。
9. 是否需要重启 EA、发送真实测试消息或更新版本。

## 5. 模块提示词模板

```text
你好，这是 EA 系统的模块实施任务。

【主责模块】
<模块编号和名称>

【需求背景】
<为什么要改，当前实际问题是什么>

【确认后的目标】
<用户最终确认的行为>

【实施范围】
- <需要修改的功能>
- <允许修改的文件或目录>

【不在范围内】
- <明确不能顺手修改的内容>

【业务规则】
1. <状态和权限规则>
2. <提醒、时间或重试规则>
3. <兼容和失败处理>

【验收标准】
1. <正常场景>
2. <边界场景>
3. <回归场景>

【工程要求】
- 先读取仓库根目录 AGENTS.md。
- 使用相对路径配置，不写死机器绝对路径。
- 保留用户和其他会话已有改动。
- 增加明确日志，日志包含任务标识、目标、状态、时间和失败原因。
- 按风险补语法、配置和行为测试。
- 更新版本号和 docs/progress-plan.md。
- 需要运行态生效时，重启 EA 并核对 /api/status。

【交付结果】
- 改动摘要和文件位置。
- 验证结果。
- 是否存在 Bug、遗漏边界、现有功能影响和性能风险。
- 未完成事项或需要回主会话决策的问题。
```

## 6. 标准推进流程

1. 用户在主会话描述问题。
2. 主会话补齐需求并确认验收口径。
3. 主会话确定唯一主责模块。
4. 主会话输出模块提示词。
5. 用户将提示词发送到对应模块会话。
6. 模块会话实施并返回结果。
7. 用户把模块结果带回主会话，主会话审核跨模块影响和下一步。
