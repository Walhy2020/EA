# M01 需求必填字段监控测试用例

更新时间：2026-08-04

测试用例版本：v1.1.0

适用 EA 版本：v0.6.18 或更高

## 1. 测试目标

验证需求总表必填字段监控在以下场景中判断、提醒和状态流转均正确：

1. 每个必填字段分别为“空值”、“`-`”和“有效值”。
2. 普通字段、人员字段、Lookup 关联字段、日期、数字和布尔值的不同接口结构。
3. 群汇总卡、自建应用个人提醒、正在处理、已完成和自动核验。
4. 打开处理页和手动刷新时读取需求总表最新数据，不显示历史缺失字段。
5. 已解决任务不能同时显示“已完成”和旧缺失字段。

## 2. 判定标准

| 数据状态 | 示例 | 预期 |
|---|---|---|
| 空值 | 字段不存在、`null`、空字符串、空数组、空对象 | 判定为缺失 |
| 横杠 | `-`、数组中的 `-`、人员或关联字段返回的 `-` | 判定为已填写，不提醒 |
| 有效值 | 文本、人员、日期、数字 `0`、布尔值 `false` | 判定为已填写，不提醒 |

说明：`-` 是业务允许的明确占位值，不等同于空值。

## 3. 测试前准备

1. 确认 EA 状态接口可访问：`http://127.0.0.1:39200/api/status`。
2. 状态接口应显示：
   - `app.version >= 0.6.18`
   - `robot.running = true`
   - `monitors.devProgress.running = true`
3. 在需求总表准备一条专用测试需求，记录需求 ID、记录 ID、项目、责任人和原始字段值。
4. 不要修改正在上线或真实生产需求；测试结束后恢复测试记录。
5. 当前试运行责任人是高文盛，测试接收人配置以 `config/dev-progress.config.json` 为准。

## 12. 快速测试流程

1. 运行第 4 节自动化命令，确认 1080 项全部通过。
2. 选一条测试需求，只留一个字段为空，触发提醒。
3. 打开个人处理页，确认显示该字段。
4. 点击“正在处理”。
5. 在总表把字段填为 `-`，点击“刷新字段”，确认字段消失。
6. 再把字段清空并刷新，确认字段重新出现。
7. 填写真实值并刷新，确认字段消失。
8. 点击“已完成”，等待约 30 秒，确认状态为已解决。
9. 查看日志，确认三次判定分别为缺失、不缺失、不缺失。

## 14. 发布准入标准

1. 自动化 1080 项全部通过，无失败字段。
2. 历史缺陷专项回归全部通过。
3. 页面不得出现“已完成或已解决，但仍显示旧缺失字段”。
4. `-`、数字 `0`、布尔值 `false` 不得误判为空。
5. 群提醒、个人提醒和状态操作不得重复发送或串任务。
6. EA 重启后状态可恢复，机器人和需求监控保持运行。
